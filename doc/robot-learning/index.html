Learn on a real robot

Mount FlexiTac on your gripper, collect visuo-tactile demonstrations and train policies, with LeFlexiTac on a low-cost arm or Touch in the Wild with a handheld gripper.

Start here once your sensor shows a live heatmap (see Stream the sensor). Learning with touch on a real robot has three parts: mount the sensor where contact happens, record demonstrations that include the tactile stream, and train a policy that uses it. Two open pipelines cover all three. The main difference between them is how you collect the demonstrations.

#Mount the sensor

FlexiTac has been mounted on many grippers and hands. These builds from the project page are good starting points for your own mount.

Mounting tips

Mount the sensor on a slightly compliant surface, such as the soft fin-ray fingers in the photos, so contact spreads over several taxels. Route the FFC cables so they don't flex at the connector while the gripper moves, and calibrate after mounting, because the mount itself changes the resting baseline.

New to robot learning? Start with LeFlexiTac. It is the lowest-cost setup, uses the sensor exactly as these docs set it up, and covers recording, training and evaluation in one toolchain. Choose Touch in the Wild when you want a lot of varied data from outside the lab, or want to build on its released dataset and encoder.

#LeFlexiTac: touch for LeRobot

LeFlexiTac↗ adds FlexiTac to LeRobot↗ on the low-cost SO-100/101 arm (LeFlexiTac calls the family SO10X). A 3D-printed jaw carries one FlexiTac pad, and the tactile map is recorded next to the camera and joint states in a standard LeRobot dataset. Four policy families take it as an extra input, switched on with --policy.use_tactile=true. On tube insertion, peg-in-hole and pen retrieval from a bag, the tactile policies beat their vision-only versions in every reported comparison (results↗).

You need: an SO-100/101 leader and follower arm pair, the printed tactile jaw, one working FlexiTac sensor with its reading board, one camera, and a Linux machine with a CUDA GPU for training. Fine-tuning Pi0.5 needs a GPU with at least 80 GB of memory.

  1. Build the arm and the tactile gripper

    Assemble the arms from the SO-ARM100 guide↗, then print the tactile Moving Jaw and Wrist Roll and fit them. LeFlexiTac docs: Hardware↗

  2. Install LeFlexiTac

    Install the fork from source in a Python 3.12 environment. pip install lerobot gives you upstream LeRobot, which has no tactile support. README: Environment setup↗

  3. Calibrate the arms and mount the sensor

    Calibrate and test teleoperation with LeRobot's SO-101 walkthrough↗, then mount the pad and confirm it with flexitac-heatmap. LeFlexiTac docs: steps 02–07↗

  4. Record demonstrations

    Record with lerobot-record and the so_tactile_follower robot type, at 30 fps. LeFlexiTac docs: step 08↗

  5. Train and evaluate

    Train with and without touch (--policy.use_tactile=true / false), then roll the checkpoint out on the arm. Train and run a policy at the same frame rate. LeFlexiTac docs: steps 09–10↗ · Practical tips↗

#Touch in the Wild: collect anywhere

Touch in the Wild↗ (NeurIPS 2025) puts a 12 × 32 FlexiTac pad on each soft finger of a handheld, UMI-style gripper with a GoPro camera. You carry it and do the task yourself, indoors or outdoors, with no robot. With it the authors collected more than 2,700 demonstrations across 43 tasks in 12 environments. That data pretrains a visuo-tactile encoder, which then conditions a Diffusion Policy that runs on an xArm 850 with the same fingers and sensors.

You need: the UMI↗ handheld gripper with Touch in the Wild's modifications and a GoPro Hero 9, two FlexiTac pads with a reading board each, a laptop with Ubuntu 22.04 and ROS 2 Humble for recording, and an NVIDIA GPU for training. To run policies, you need a uFactory xArm 850 with the xArm Gripper, the printed finger holder and GoPro mount from the gripper guide, and an HDMI capture card for the GoPro feed. The full released dataset is large: the pretraining set alone is about 88 GB.

  1. Build the gripper

    Build the UMI gripper, then apply Touch in the Wild's top plate and finger holders and add the two pads. Gripper guide↗

  2. Set up the recording laptop

    Give each reading board a fixed device name, then install the ROS 2 tactile packages. Data collection: device names↗ · ROS 2 setup↗

  3. Collect demonstrations

    Record the tactile streams with ROS 2 while the GoPro films. A QR code shown to the camera before each demonstration lines up video and touch. Data collection protocol↗

  4. Turn the recordings into a dataset

    Run the SLAM pipeline on the session folder to get a training dataset. README: SLAM pipeline↗

  5. Pretrain the encoder, or download it

    Pretrain the visuo-tactile encoder on your data or the released dataset↗, or start from the pretrained checkpoint↗. README: Pretraining↗ · Evaluate a checkpoint↗

  6. Train and run the policy

    Train the tactile Diffusion Policy, then run it on the xArm 850. README: Training↗ · Real-world deployment↗

It needs different firmware

Touch in the Wild reads the boards with its own code, not PyFlexiTac: a ROS 2 node while recording, and serial readers when running a policy. Both expect the older text output, 16 lines of 32 numbers per frame. The firmware in Stream the sensor sends binary frames instead, so a board flashed from these docs won't work with Touch in the Wild as it is, and its repositories don't include matching firmware. Ask in its issues↗ or on the Discord↗ before you build.

#Research background

3D-ViTac↗ (CoRL 2024) is where this line of work started. It introduced the sensor now called FlexiTac-V1 and the visuo-tactile point cloud, which places each taxel in 3D next to the camera points and feeds both to one policy. For now its training-code repository↗ only points to the pre-training stage of VT-Refine. The authors say that stage uses the same setup but runs in simulation, on VT-Refine's plug–socket data rather than 3D-ViTac's own tasks. 3D-ViTac's data and real-robot code have not been released yet.

For more work built on FlexiTac, see Awesome FlexiTac↗. If a step in a project's guide doesn't work, open an issue in that project's repository.
